# 고객 공사 진행 현황 페이지 설계

작성일: 2026-10-17 · 상태: 검토 대기 · 병합: 진행 중인 묶음(#7·#8·#9·휴지통·보안) 다음 묶음

## 1. 목적

계약한 고객이 알림톡 버튼 하나로 자기 현장의 공사 진행 상황(사진, 공정, 작업 메모)을 확인하게 한다. 지금은 직원이
일일 보고서 이미지를 만들어 내려받고 카톡으로 따로 보내며, 기록은 그 PC 브라우저에만 남는다.

### 결정 사항 (대표님 답변)

| 질문 | 결정 |
|---|---|
| 보낼 안내 | 사진과 진행 현황 링크 (고객용 페이지 + 알림톡 버튼) |
| 페이지 내용 | 날짜별 현장 사진, 공정 일정과 진행률, 작업 메모, 연락처 |
| 고객 확인 | 비밀 링크 + 휴대폰 번호 뒷자리 4자리 |
| 알림톡 발송 | 직원이 올릴 때 골라서 발송 (자동 발송 없음) |
| 올리는 곳 | 기존 일일 보고서 창 |
| 구현 방식 | A안: Firestore 기록 + Sanity 사진 + 홈페이지 안 고객 페이지 |
| 연락처 | 회사 대표번호(031-381-0489)만 |
| 병합 시점 | 다음 묶음. 보안 강화 작업 위에서 만든다 |

## 2. 저장 구조

### 진행 기록: Firestore `siteProgressUpdates`

| 필드 | 내용 |
|---|---|
| `siteId` | 현장 ID |
| `reportDate` | 작업 날짜 (`YYYY-MM-DD`) |
| `designer` | 담당 실장 이름 (일일 보고서 입력값) |
| `workDetail` | 작업 메모 (줄바꿈 유지) |
| `photos` | `[{ assetId, url, width, height }]` (올린 순서 유지) |
| `createdAt`, `createdBy` | 올린 시각, 올린 계정 |
| `notifyLog` | `[{ sentAt, ok, error?, by }]` 알림톡 발송 기록 |

### 현장 정보 추가 필드 (`officeSites`)

| 필드 | 내용 |
|---|---|
| `progressCode` | 진행 현황 코드. `crypto.randomBytes(16)`의 base64url (22자) |
| `progressEnabled` | 링크 켜기/끄기 |
| `progressCodeCreatedAt` | 코드를 만든 시각 |
| `progressAccess` | `{ failedCount, lockedUntil }` 뒷자리 확인 실패 기록 |

### 사진

- 브라우저에서 긴 변 1600px, JPEG 품질 0.82로 줄인 뒤 올린다.
- 저장은 프로젝트 사진과 같은 Sanity 에셋 업로드 흐름을 쓴다 (`SANITY_WRITE_TOKEN`, 서버 경유). Firebase Storage는
  쓰지 않는다 (`docs/WEVE_WORKING_RULES.md`).
- 고객 페이지는 Sanity 이미지 CDN의 크기 변환을 쓴다 (목록 `w=800`, 크게 보기 `w=1600`), 지연 로딩.
- Sanity 에셋 주소는 데이터셋이 비공개여도 주소를 알면 열린다. 주소에 추측할 수 없는 해시가 들어가므로 비밀 링크와 같은
  수준으로 본다.

### 기존 기능

- 일일 보고서의 로고 이미지 만들기·내려받기와 브라우저 저장 기록은 그대로 둔다. 옛 기록을 옮기지 않는다.
- 진행 기록을 지우면 고객 페이지에서 바로 사라진다. Sanity 에셋은 지우지 않는다 (다른 곳에서 참조 가능성, 복구 여지).

## 3. 고객 페이지

### 주소와 응답

- `app/progress/[code]/page.tsx` 서버 컴포넌트. `dynamic = 'force-dynamic'`, 메타데이터 `robots: noindex, nofollow`.
- 응답 헤더 `Cache-Control: private, no-store`. 사이트맵·RSS에 넣지 않는다.
- 코드로 현장을 찾을 때는 서버(Firestore 서비스 계정)에서만 읽는다. 브라우저는 Firestore에 직접 접근하지 않는다.

### 뒷자리 확인

1. 코드가 없거나 `progressEnabled`가 꺼져 있으면: "링크가 꺼져 있습니다. 위브디자인(031-381-0489)으로 문의해 주세요."
2. 유효한 쿠키가 없으면 "휴대폰 번호 뒷자리 4자리" 입력 화면을 보여준다.
3. `POST /api/progress/verify { code, last4 }`
   - 고객 번호: 현장의 `customerPhone`, 없으면 연결된 고객(`customerId`)의 번호. 숫자만 비교한다.
   - 고객 번호가 없으면 확인할 수 없다는 안내 (관리자 화면은 링크를 켤 때 경고한다).
   - 성공: 쿠키 `wp_<sha256(code) 앞 16자>` = `exp.HMAC(key, code|뒷자리|exp)`, 180일, `HttpOnly; Secure; SameSite=Lax; Path=/progress`.
   - 실패: `failedCount + 1`. 5회가 되면 `lockedUntil = 지금 + 15분`, 잠긴 동안은 확인하지 않고 남은 시간을 안내한다.
     성공하면 실패 기록을 지운다.
4. 서명 키: 보안 강화 설계와 같은 순서로 정한다. `MANAGER_SESSION_SECRET`에서 `HMAC(secret, "weve-progress-v1")`로
   파생, 없으면 `SANITY_WRITE_TOKEN`에서 같은 방식으로 파생. 둘 다 없으면 확인 API가 500.
5. 새 링크로 바꾸면 코드가 바뀌어 예전 쿠키와 링크가 모두 무효가 된다. 고객 번호가 바뀌어도 쿠키가 무효가 된다.

### 화면 구성 (휴대폰 우선)

1. 위브디자인 로고, 현장명, "OOO 고객님의 공사 진행 현황"
2. 진행률 바, 공사 기간(첫 공정 시작일 ~ 마지막 공정 종료일), 지금 공정 / 다음 공정
3. 공정 일정 목록: 완료 ✓ / 진행 중 / 예정, 공정 이름과 날짜
4. 진행 기록: 날짜별 카드(최신순), 담당 실장 이름, 작업 메모, 사진 격자. 사진을 누르면 크게 보고 좌우로 넘긴다.
5. 문의: 회사 대표번호 전화 버튼

### 공정과 진행률 계산

- 기준 견적: 해당 현장의 `versionType === 'final'` 중 가장 최근, 없으면 가장 최근 버전의 `scheduleJson`.
- 공정 상태 (한국 시간 기준 오늘): `endDate < 오늘` 완료, `startDate <= 오늘 <= endDate` 진행 중, 그 외 예정.
  공정의 `progress` 값이 100이면 날짜와 상관없이 완료로 본다.
- 전체 진행률: 공정별 진행도(`progress`가 0보다 크면 그 값, 0이거나 없으면 날짜 상태로 예정 0 / 진행 중 50 / 완료 100)를
  `durationDays`로 가중 평균. `progress` 기본값이 0이므로 0은 "입력 안 함"으로 본다.
- 공정 일정이 없으면 진행률 영역을 숨기고 진행 기록만 보여준다.

### 보여주지 않는 것

견적 금액, 단가, 원가, 마진, 거래처 이름·연락처, 공정 메모(`memo`), 담당 실장 외 직원 정보.

## 4. 관리자 화면

### 현장 정보: "고객 진행 현황 링크"

- 링크 켜기·끄기. 처음 켤 때 코드를 만든다. 고객 번호가 없으면 경고를 보여주고 켜지 않는다.
- 링크 복사, 새 링크로 바꾸기(확인창: "이전 링크와 고객 확인 기록이 모두 무효가 됩니다").
- 미리보기: 관리자 세션으로 `GET /api/manager/progress?siteId=&preview=1`이 고객 화면과 같은 데이터를 돌려주고, 관리자
  화면 안에서 같은 컴포넌트로 보여준다. 뒷자리 확인을 하지 않는다.
- 알림톡 발송 기록 목록.

### 일일 보고서 창

- 기존 "보고서 이미지 만들기"는 그대로.
- 추가: "고객 진행 현황에 올리기" (현장 링크가 켜져 있으면 기본 켜짐), "고객에게 알림톡 보내기" (기본 꺼짐).
- "올리기": 사진 줄이기 → 업로드 → 기록 저장 → (선택 시) 알림톡 발송. 진행 상태와 결과를 창 안에 보여준다.
- 이 현장의 서버 기록 목록: 날짜, 메모 요약, 사진 수, 알림 발송 여부, 삭제(확인창), 알림 다시 보내기.

### API (관리자 인증)

- `GET /api/manager/progress?siteId=` 링크 상태와 기록 목록
- `POST /api/manager/progress`
  - `multipart`: `uploadPhoto` (siteId, file 1장) → `{ assetId, url, width, height }`. Vercel 요청 크기 제한(약 4.5MB)
    때문에 사진은 한 장씩 올린다.
  - JSON: `createUpdate` (siteId, reportDate, designer, workDetail, photos[] = uploadPhoto 결과, notify),
    `deleteUpdate`, `setLink` (`enable` / `disable` / `rotate`), `notify` (updateId, `resend` 여부)
- 권한: 보안 강화 작업의 서버 권한 검사를 따른다. `sites` 권한이 있어야 한다.

## 5. 알림톡

- 알리고 발송 흐름은 기존 계약 완료 알림톡과 같은 방식(서버에서 `akv10/alimtalk/send`)을 쓴다.
- 받는 사람: 현장 고객 번호. 기록 한 건당 한 번 발송, 다시 보내려면 `resend`.
- 변수: `#{고객명}`, `#{현장명}`, `#{날짜}`, 버튼 링크의 `#{코드}`.
- 환경 변수

```text
ALIGO_PROGRESS_TEMPLATE_CODE=
ALIGO_PROGRESS_MESSAGE_TEMPLATE=   # 승인된 템플릿 문구와 글자까지 같아야 한다
ALIGO_PROGRESS_BUTTON_JSON=        # 승인된 버튼과 같게. 링크에 #{코드}
ALIGO_PROGRESS_SUBJECT=공사 진행 안내   # 선택
```

- 공통 값 `ALIGO_API_KEY`, `ALIGO_USER_ID`, `ALIGO_SENDER_KEY`, `ALIGO_SENDER_PHONE`, `ALIGO_TEST_MODE`는 기존 것을 쓴다.
- 템플릿 예시 (대표님이 알리고에 등록·승인)

```text
[위브디자인] 공사 진행 안내
#{고객명} 고객님, #{현장명} 현장의 #{날짜} 공사 진행 상황이 등록되었습니다.
아래 버튼을 눌러 사진과 공정 일정을 확인해 주세요.
문의: 031-381-0489

버튼(웹링크) 진행 현황 보기
  모바일웹 링크: https://www.wevedesign.co.kr/progress/#{코드}
  PC 링크: 같은 주소
  채널추가: 체크하지 않음 (정보성 알림톡)
```

- 구현 시 알리고 문서로 버튼 파라미터 이름과 변수 링크 형식을 다시 확인한다.

## 6. 오류 처리

| 상황 | 처리 |
|---|---|
| 사진 업로드 실패 | 기록을 만들지 않는다. 실패한 사진 이름과 다시 시도 안내 |
| 기록 저장 성공, 알림톡 실패 | 기록은 남긴다. `notifyLog`에 실패 이유, 창에 "다시 보내기" |
| 템플릿 환경 변수 없음 | "알림톡 템플릿 설정이 필요합니다". 기록 올리기는 그대로 된다 |
| 고객 번호 없음 | 링크 켜기와 알림 발송을 막고 안내 |
| 코드 없음/링크 꺼짐 | 고객 페이지 안내 화면 (어떤 현장인지 드러내지 않는다) |
| 뒷자리 5회 실패 | 15분 잠금, 남은 시간 안내 |

## 7. 검증

1. 단위 스크립트: 쿠키 서명·검증·만료, 코드 교체 후 무효, 잠금 계산, 진행률 계산(진행도 값 있음/없음, 공정 없음).
2. 로컬 화면(내장 브라우저, API는 fetch 모킹): 일일 보고서 창 올리기 흐름, 기록 목록·삭제, 링크 켜기/끄기/바꾸기, 미리보기.
3. 고객 페이지: 뒷자리 확인 성공/실패/잠금, 링크 꺼짐, 휴대폰 크기 화면, 금액·거래처 정보가 응답에 없는지 확인.
4. `npm run build` 통과.
5. 미리보기 배포에서 `ALIGO_TEST_MODE=Y`로 알림톡 요청 형식 확인. 실제 발송은 템플릿 승인 뒤 대표님 번호로 한 번.

## 8. 배포 순서 (대표님 작업)

1. 알리고에 5절(알림톡)의 템플릿을 등록하고 승인을 받는다 (보통 1~3일). 2026-10-17 대표님이 등록 진행 중.
2. 승인되면 Vercel에 `ALIGO_PROGRESS_*` 값을 넣는다.
3. 진행 중인 묶음(보안 포함)이 병합된 뒤 이 기능을 병합·배포한다.
4. 테스트 현장에서 링크를 켜고, 대표님 번호를 고객 번호로 넣어 전체 흐름을 한 번 확인한다.

## 9. 범위 밖

- 자동 발송(매일 저녁 등), 고객 댓글·답장
- 사진을 서버를 거쳐 보여주는 방식(완전 비공개 사진)
- 브라우저에 저장된 예전 일일 보고서 옮기기
- 고객 여러 명(가족) 번호 등록
