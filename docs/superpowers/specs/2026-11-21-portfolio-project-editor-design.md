# 시공 사례(포트폴리오) 등록·수정 한 화면으로

작성일: 2026-11-21 · 상태: 설계 승인(2026-11-21)

## 1. 목적과 범위

홈페이지 > Project 관리 탭에는 시공 사례를 저장하는 길이 둘 있고, 서로 넣을 수 있는 내용이 다르다.

- **현장 폴더 한번에 업로드**(`page.tsx` `uploadProjects` → `app/api/manager/bulk-upload`): 새 사례를 만드는 유일한 길. 분류·주거 형태·지역·평수·설명·메인 표시만 받고, 올리는 즉시 홈페이지에 공개된다. 여러 폴더를 올리면 모두 같은 값이 들어간다.
- **Project 분류 관리**(수정 폼, `saveProjectClassification` → `/api/manager/office` type `project`, 대표 사진은 `project-main-image`로 따로 즉시 저장): 연도·자재·블로그·순서·16:9 중심점을 받지만 시공 전 사진·공간별 사진 묶음은 못 다룬다.

이를 **'시공 사례' 한 화면**으로 합친다. 폴더를 올리면 같은 정보 폼이 바로 열리고, 숨김 상태로 저장했다가 정보를 다 채운 뒤 공개한다. 수정도 같은 폼이다.

성공 기준:

- 새 사례도 기존 사례와 똑같은 칸을 채울 수 있다.
- 새로 올린 사례는 [홈페이지에 공개]를 누르기 전에는 홈페이지에 보이지 않는다.
- 같은 폴더를 다시 올려도 공개 여부·메인 표시·직접 넣은 정보가 풀리지 않는다.
- 저장 버튼은 하나다(대표 사진 고르기도 같은 저장에 포함).
- 아래 6절의 버그가 사라진다.
- 작업 규칙의 "만들기·수정 모두에 대표 사진 선택과 16:9 위치 조정"을 지킨다.

### 결정 사항 (사용자 답변, 2026-11-21)

| 질문 | 결정 |
|---|---|
| 맞추는 방법 | **A. 한 화면**(올리기 → 같은 폼 → 숨김 저장 → 공개) |
| 주거 형태(`siteType`, 홈페이지에 안 보임) | 폼에서 뺀다(내 판단, 되돌리기 쉬움). Sanity 필드와 기존 값은 그대로 |
| 이름·분류를 바꿔 주소가 바뀐 경우 | 옛 주소에서 새 주소로 넘겨 준다 |

### 하지 않는 것

- 사진을 한 장씩 올리는 방식으로 바꾸기. 한 번에 올리는 용량 제한(압축 후 약 3.8MB, Vercel 요청 크기)은 그대로 둔다(후속 과제).
- 관리 화면에서 사례 삭제(지금처럼 Sanity Studio). 
- 사진 묶음에 사진을 한 장씩 더하기(같은 폴더 다시 올리기로 대신).
- 홈페이지 모양 바꾸기. '0' 표시 같은 버그만 고친다.
- Sanity Studio 스키마 변경(Studio를 평소 업무에 쓰지 않는다는 규칙 유지).

## 2. 방법 비교 (고른 것: A)

| | A. 한 화면 (선택) | B. 두 패널 유지, 칸만 맞춤 |
|---|---|---|
| 새 사례 정보 | 올린 직후 같은 폼에서 | 업로드 폼에 칸 추가 |
| 공개 시점 | 정보를 채운 뒤 직접 | 올리면 바로(또는 체크) |
| 여러 폴더 | 사례마다 따로 채움 | 모두 같은 값 |
| 관리 | 칸 목록 하나 | 같은 칸을 두 곳에서 |

## 3. 화면

홈페이지 탭 안의 'Project 관리'를 **'시공 사례'**로 이름을 바꾸고, 왼쪽 목록 · 오른쪽 편집 2단으로 둔다. 이 탭에 남아 있던 빈 '홈페이지 관리' 패널과 그 저장 버튼은 다른 홈페이지 설정 탭으로 옮기거나 지워 저장 버튼이 섞이지 않게 한다(빌더가 실제 쓰임을 확인).

### 3.1 목록 (왼쪽)

```
[+ 새 시공 사례 올리기]
[검색: 이름·지역      ]  [분류 ▾]  [전체|공개|숨김]
─────────────────────────────
▣ 평촌 어바인퍼스트 34평   아파트 · 안양   공개 · 메인
▣ 산본 래미안 2차          아파트 · 군포   숨김
```

- 대표 사진 작은 그림, 이름, 분류 · 지역, 상태(공개/숨김, 메인이면 '메인').
- 정렬: 홈페이지와 같은 순서(메인 먼저 → 보이는 순서 → 최근).

### 3.2 새 시공 사례 올리기

```
새 시공 사례 올리기
  공간 분류*   [아파트 ▾]  또는 새 분류 [        ]
  폴더 선택    [폴더 고르기]   (여러 개 가능)
               평촌 어바인퍼스트 34평  사진 32장 (대표 1 · 시공 전 1)
               산본 래미안 2차         사진 18장
  파일 이름 규칙: 대표·cover → 대표 사진, 시공전·before → 시공 전 사진,
                 거실1·주방2 → 공간별 묶음과 순서
                                          [올리기]
```

- 올리기에서 받는 것은 **공간 분류와 폴더**뿐이다. 지역·평수·설명·메인 표시는 올린 뒤 폼에서 사례마다 넣는다.
- 사진 압축과 한 번에 보내는 방식, 파일 이름으로 대표·시공 전·묶음을 나누는 규칙은 지금 그대로다.
- 폴더 이름과 같은 이름의 사례가 이미 있으면 올리기 전에 폴더마다 묻는다: "같은 이름의 시공 사례가 있습니다" [그 사례의 사진 바꾸기] [새 사례로 만들기]. 같은 이름이 여럿이면 어느 사례인지 고르게 한다. 묻지 않고 이름으로 저절로 덮어쓰지 않는다(내 판단: 직원이 폴더 이름으로 만든 사례 이름을 다듬는 일이 많아, 이름만으로는 같은 사례를 믿고 찾을 수 없다).
- 올리면 결과를 보여 준다: "새로 만듦 2 · 사진 바꿈 0 · 건너뜀 0". 새로 만든 사례는 **숨김**이다. 하나만 올렸으면 그 사례의 편집 폼을 바로 연다. 여럿이면 목록에서 '숨김'으로 걸러 보여 준다.
- 올린 뒤 폼을 비운다(작업 규칙).
- 이미 있는 사례의 사진을 통째로 바꾸는 기본 길은 편집 폼의 **[사진 다시 올리기]**다(폴더 하나를 골라 그 사례에 올림). 이름을 바꾼 사례도 이 버튼으로 바꾼다.

### 3.3 편집 폼 (오른쪽, 새 사례와 기존 사례 공통)

```
산본 래미안 2차                                [숨김]  [홈페이지에 공개]
  ⓘ 아직 홈페이지에 보이지 않습니다. 정보를 채운 뒤 공개하세요.   (숨김일 때)
기본 정보
  이름*        [산본 래미안 2차    ]   공간 분류* [아파트 ▾]
  지역         [군포        ]   평수 [  32 ]   시공 연도 [2026]
  주요 자재    [                          ]
  블로그 링크  [blog.naver.com/…           ]
  짧은 설명    [                          ]  (줄바꿈 그대로 보임)
  보이는 순서  [   ]  (비우면 순서 없음, 순서 있는 사례 뒤)
  ☐ 메인에도 보이기
대표 사진
  [상세 사진 중 고르기 ▾]  [새 사진 올리기]
  ┌ 목록 카드(4:3) ┐  ┌ 사례 창 위(16:9) ┐   ← 같은 중심점으로 두 틀을 같이 보여 줌
  중심점: 사진을 눌러 정하기 · X [50] Y [50]
시공 전 사진
  [그림]  [바꾸기]  [빼기]       (없으면 [올리기])
공간별 사진 (묶음 3 · 사진 30장)                 [사진 다시 올리기]
  거실 (8장)   [이름 바꾸기] [↑] [↓]
     [그림][그림][그림]… 각 사진에 [빼기]
  주방 (6장)   …
                                                     [저장]
```

- **옛 방식 낱장 사진(`gallery`)**: 운영 데이터 8개 중 2개는 묶음(`galleryGroups`) 없이 옛 낱장 사진만 있다(2026-11-21 확인). 이런 사례는 '공간별 사진' 자리에 "옛 방식 사진 N장 (묶음 없음)"으로 읽기 전용으로 보여 주고 [묶음으로 바꾸기]를 둔다. 누르면 그 사진들을 순서대로 '사진'이라는 묶음 하나로 옮기고, [저장] 때 묶음을 쓰고 `gallery`를 지운다. [사진 다시 올리기]로 바꿀 때도 `gallery`를 지운다. 홈페이지는 묶음이 없을 때만 `gallery`를 보여 주므로, 묶음 사진을 모두 빼서 옛 사진이 다시 나타나는 일이 없도록 묶음으로 바꾼 뒤에만 사진을 뺄 수 있다.

- **저장 버튼 하나**로 기본 정보·대표 사진 선택·중심점·시공 전 사진·묶음 변경을 함께 저장한다. 대표 사진이나 시공 전 사진을 '새로 올리기'하면 사진 파일은 바로 Sanity에 올라가지만, 사례에 붙는 것은 [저장] 때다. 저장하지 않고 다른 사례를 고르면 "저장하지 않은 변경이 있습니다"를 묻는다.
- **공개/숨기기**는 저장과 따로 있는 버튼이다. 공개하려면 이름·공간 분류·대표 사진이 있어야 한다. 저장하지 않은 변경이 있으면 저장부터 하라고 알린다.
- **대표 사진 표시 위치 드롭다운은 없앤다**(효과가 없었다, 6절). 중심점(X/Y)만 남긴다.
- 중심점 미리보기는 홈페이지에서 실제로 잘리는 두 모양(목록·메인 카드 4:3, 사례 창 위 16:9)을 같이 보여 준다.
- 묶음 이름은 자유 입력(1~20자). 사진 순서 바꾸기는 하지 않는다(파일 이름 숫자 순서 유지).
- 주거 형태 칸은 없다.

## 4. 데이터 규칙

순수 모듈 `app/lib/project-form.ts`(import 없음)에 모아 화면과 서버가 같이 쓴다.

- **이름** 앞뒤 공백 제거, 1~80자, 필수. **공간 분류** 필수.
- **평수·보이는 순서**: 비우면 필드를 지운다(`unset`). 숫자만, 평수는 0보다 크게, 순서는 0 이상 정수. 빈칸을 0으로 저장하지 않는다.
- **이미 저장된 0**(운영: 순서 0이 3개, 모두 메인 / 평수 0이 1개, 2026-11-21 확인): 정리 스크립트로 지우지 않는다(내 판단). 순서 0은 폼에 '0'으로 그대로 보여 주고(지금 폼은 빈칸으로 보여 줘서 헷갈렸다) 홈페이지 순서도 지금대로 둔다. 그래서 배포해도 홈페이지 순서는 바뀌지 않고, 직원이 고칠 때만 바뀐다. 평수 0은 '없음'으로 취급해 홈페이지에 보이지 않게 한다(6절).
- **같은 이름**: 다른 사례와 이름이 같으면 저장할 때 알려 주되 막지는 않는다(올리기는 대상 사례를 직접 고르므로 같은 이름이어도 문제가 없다).
- **시공 연도**: 비우거나 4자리 연도.
- **블로그 링크**: 비우거나, `http(s)://`가 없으면 `https://`를 붙인 뒤 URL로 읽혀야 한다. 아니면 "블로그 주소를 확인해 주세요".
- **설명**: 앞뒤 공백만 자르고 줄바꿈 유지.
- **중심점** X/Y: 0~100, 기본 50.
- **대표 사진 alt**: 지금처럼 "{이름} 대표 사진"(시공 전은 "{이름} 시공 전 사진").

## 5. 서버

### 5.1 올리기 — `app/api/manager/bulk-upload/route.ts`

- 폴더마다 화면이 정한 대상을 함께 보낸다: `new`(새 사례) 또는 `replace:<사례 id>`(그 사례의 사진 바꾸기). 서버는 **이름으로 사례를 찾지 않는다.** `replace` 대상은 문서 종류를 확인하고(`isSanityIdWritable`, 초안 `drafts.` 제외), 없으면 그 폴더만 실패로 남긴다.
- 새로 만드는 사례는 `isVisible: false`, `featured: false`. 사례 id는 무작위(`project-` + 무작위)로 만든다. 지금처럼 이름 해시로 만들면, 이름을 바꾼 사례와 같은 이름의 폴더를 새로 올릴 때 id가 겹쳐 실패한다(6절).
- **사진 바꾸기**는 사진만 바꾼다: 공간별 묶음 전체, 시공 전 사진(새 폴더에 있을 때만, 없으면 기존 유지), 대표 사진(새 폴더에서 정해진 사진), 옛 `gallery`는 지운다. **이름, `isVisible`, `featured`, 분류, 지역·평수·설명·연도·자재·블로그·순서는 건드리지 않는다.** 대표 사진이 바뀌면 중심점을 50/50으로 되돌린다.
- 폼 필드 `siteType`, `location`, `description`, `area`, `featured`는 더 받지 않는다.
- 한 사례가 실패해도 이미 처리한 사례 결과는 돌려주고, 실패한 사례는 결과에 이유와 함께 남긴다(지금은 첫 실패에서 전체가 500).

### 5.2 저장 — `/api/manager/office` type `project`

- 지금 경로를 쓴다. 받는 필드: 4절의 기본 정보, `mainImage`(자산 참조), `mainImagePositionX/Y`, `beforeImage`(자산 참조 또는 빼기), `galleryGroups`(묶음 이름·순서 변경과 사진 빼기를 반영한 배열). 비운 숫자는 `unset`.
- `mainImagePosition`(드롭다운 값)은 더 쓰지 않는다. 기존 값은 남아 있어도 화면이 무시한다(이미 그렇게 동작함).
- 공개/숨기기는 `isVisible`만 바꾸는 작은 요청으로(내 판단: 같은 경로에 `{ id, visibleOnly: true, isVisible }` 또는 별도 동작, 빌더가 정함). 공개는 서버에서도 이름·분류·대표 사진을 확인한다.
- 사진 파일 올리기는 지금 `project-main-image`의 자산 업로드 부분을 쓰되, 사례 문서를 바로 고치지 않고 자산 id만 돌려주게 한다. 시공 전 사진도 같은 길.
- 모든 Sanity 쓰기는 지금처럼 문서 종류를 먼저 확인한다(`isSanityIdWritable`).

### 5.3 CLI 스크립트

`scripts/upload-project-folders.mjs`도 같은 규칙(새 사례는 숨김·무작위 id, 다시 올릴 때 공개 여부와 직접 넣은 정보 유지)을 따르게 한다. 새 분류의 slug 규칙도 관리 화면과 같게(`slugValue`).

## 6. 함께 고칠 버그

| 버그 | 고치는 곳 |
|---|---|
| 대표 사진 표시 위치 드롭다운이 효과 없음(X/Y가 항상 숫자로 저장돼 무시됨) | 드롭다운 제거(3.3) |
| 평수를 비우고 저장하면 0이 저장되고 홈페이지에 '0'이 보임(`{project.area && …}`) | 4절 `unset` + 홈페이지의 해당 표시 조건을 `area > 0`으로(모양은 그대로) |
| 보이는 순서를 비우면 0이 저장돼 1·2·3보다 앞에 섬 | 4절 `unset` + 홈페이지 정렬에서 순서 없는 사례를 뒤로(`coalesce(displayOrder, 99999)`) |
| 이름을 바꾼 사례를 원래 폴더 이름으로 다시 올리면 500, 올라간 사진이 고아로 남음 | 5.1 무작위 id |
| 같은 폴더를 다시 올리면 숨긴 사례가 공개되고 메인 표시가 풀림 | 5.1 |
| 중심점 미리보기(16:9)와 목록 카드(4:3)가 다르게 잘림 | 3.3 두 틀 미리보기 |
| 이름이 비어도 저장됨, 블로그 주소에 https가 없으면 깨진 링크 | 4절 |
| 이름·분류를 바꾸면 사례 주소가 바뀌어 옛 주소가 404 | 아래 6.1 |

### 6.1 옛 주소 넘겨 주기 (`app/portfolio/[slug]/page.tsx`)

- 주소는 `분류 + 이름`의 slug 뒤에 사례 id의 끝 8자리를 붙인다(`app/lib/seo-utils.ts` `projectSlug`). 주소로 사례를 못 찾으면, 주소 끝 8자리로 사례를 찾아 지금의 정식 주소로 **영구 이동(308)** 시킨다. 끝 8자리가 맞는 사례가 정확히 하나일 때만.
- 정식 주소·사이트맵·구조화 데이터는 지금 그대로다.

## 7. 테스트

- `tests/project-form.test.mjs`: 4절 규칙 전부(빈 숫자 → unset, 0 처리, 연도, 블로그 보정과 거절, 이름 필수, 중심점 범위).
- 올리기 판단(순수 함수로 분리): `new`는 이름이 같아도 새로 만듦, `replace:<id>`는 그 사례만 사진 바꿈, 사진 바꿀 때 지켜지는 필드 목록(이름 포함), `gallery` 지우기, 대표 사진이 바뀌면 중심점 초기화, 무작위 id. 화면 쪽: 폴더 이름과 같은 사례가 하나/여럿/없을 때 묻는 내용.
- 옛 방식 사진: [묶음으로 바꾸기] 결과(순서 유지, '사진' 묶음 하나), 저장 때 `gallery` 지움, 바꾸기 전에는 사진 빼기 불가.
- 저장된 순서 0은 폼에 '0'으로 보이고 그대로 저장되는지, 평수 0은 홈페이지에 안 보이는지.
- 옛 주소 판단: 끝 8자리로 찾기, 여러 개면 404, 정식 주소면 이동 없음.
- `npm test`, `npm run build`. 운영 확인: 폴더 하나 올리기 → 숨김 확인(홈페이지에 안 보임) → 정보 채워 공개 → 이름 바꾸기 → 옛 주소 이동 → 편집 폼의 [사진 다시 올리기]로 원래 폴더 올리기 → 이름·공개·메인 유지 확인 → 같은 이름 폴더를 새로 올릴 때 묻는지 확인. 옛 방식 사진 사례 하나를 묶음으로 바꿔 홈페이지 사진이 그대로인지 확인.

## 8. 작업 규칙 문서 (Portfolio)

- 새 시공 사례는 숨김으로 만들어지고, 정보를 채운 뒤 직원이 공개한다.
- 다시 올리기는 사진만 바꾸고 공개 여부·메인 표시·직접 넣은 정보를 지킨다.
- 비운 숫자는 0이 아니라 '없음'. 블로그 주소는 https 보정.
