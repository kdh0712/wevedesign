# 견적 템플릿: 평형별 템플릿 만들기와 공사 골라 불러오기

작성일: 2026-10-22 · 상태: 검토 대기

## 1. 목적과 범위

20평형·30평형·40평형처럼 자주 쓰는 견적을 **템플릿**으로 미리 만들어 둔다. 새 현장에서는 템플릿을 불러와 고쳐서
견적서를 만든다. 템플릿은 풀 공사 기준으로 만들고, 불러올 때 그 현장에서 하지 않는 공사(예: 욕실)를 체크 해제해서
나머지만 불러온다. 불러올 때 단가는 그때의 최신 자재 DB 단가를 쓴다.

성공 기준:

- 견적 화면의 버튼으로 템플릿 창을 열어, 현장과 상관없이 템플릿을 만들고 고치고 복사하고 지울 수 있다.
- 템플릿을 불러올 때 카테고리와 공간을 체크해서 고르고, 둘 다 켜진 줄만 들어온다.
- DB에서 고른 줄은 불러오는 순간의 DB 단가가 고객 단가·실행 단가 모두에 들어간다.
- DB에서 단가를 찾지 못한 줄은 템플릿 단가로 들어오고, 어떤 줄인지 화면에 알려 준다.
- 템플릿은 현장·매출·대시보드·직원 앱·고객 진행 현황 어디에도 섞이지 않는다.
- 불러오기 한 번에 보통 Firestore 읽기 1번으로 최신 단가를 확인한다.

### 결정 사항 (대표님 답변, 2026-10-22)

| 질문 | 결정 |
|---|---|
| 만드는 방식 | A: 템플릿 전용 저장소 + 템플릿 작업 창 (가짜 현장 방식·저장만 하는 방식은 쓰지 않음) |
| 불러올 때 고르는 기준 | 카테고리와 공간 둘 다. 둘 다 체크된 줄만 불러온다 |
| 최신 단가를 넣을 곳 | 고객 단가·실행 단가 둘 다 DB 단가로 |
| 넣는 방식 | 빈 견적이면 바로 넣고, 항목이 있으면 바꾸기 / 뒤에 덧붙이기 / 취소 중에서 묻는다 |
| 템플릿에 담는 것 | 견적 항목만 (공정표·메모·발주서·추가 항목은 담지 않음) |
| 기존 견적에서 복사해 시작 | 넣는다 |
| 자재 DB 최신 확인 | 자재 DB 버전만 읽어 비교하고, 바뀌었을 때만 전체를 새로 읽는다 |

### 하지 않는 것

공정표·메모·발주서를 템플릿에 담기, 평형에 따라 수량 자동 조정, 직원 앱(휴대폰)에서 템플릿 불러오기,
템플릿 버전 기록, 예전 Sanity 저장 방식 지원(아래 3.1).

## 2. 화면

### 2.1 템플릿 관리 창

견적 화면 위쪽 도구 줄에 **"템플릿 관리"** 버튼을 둔다. 누르면 큰 창이 열린다.

**목록**: 템플릿마다 이름, 항목 수, 고객 합계(템플릿에 적힌 단가 기준), 마지막 수정일·수정한 직원.
버튼은 새로 만들기, 복사(이름 뒤에 " 복사"를 붙여 새 템플릿으로), 이름 바꾸기, 삭제(한 번 더 확인).

**작업 화면** (목록에서 하나를 누르면 열린다):

- 줄마다 공간, 카테고리, 품명, 규격, 단위, 수량, 고객 단가, 실행 단가, 비고. 공간은 견적 화면과 같은 목록
  (`defaultSpaces`)에서 고른다. 줄 추가·삭제·순서 바꾸기를 할 수 있다.
- **DB에서 추가**: 견적 화면의 자재 고르기 창(`MaterialPickerModal`)을 그대로 띄운다. 공통 항목 고르기도 같다.
  고른 줄에는 그 DB 항목의 id가 기억된다(3.2).
- **기존 견적에서 복사**: 현장을 고르고, 그 현장의 견적 버전을 골라 견적 항목을 가져온다. 지금 작업 화면에 줄이
  있으면 바꾸기 / 덧붙이기 / 취소를 묻는다. 가져온 줄의 DB 연결은 4장 순서 2로 찾는다.
- DB와 연결되지 않은 줄(4장 순서 1·2로 찾지 못하는 줄)은 줄 옆에 **"DB에서 못 찾음"**이 붙는다. 그 줄을 DB에서
  다시 고르면 표시가 사라진다. 이 표시는 화면에서만 계산하고 저장하지 않는다.
- **저장**. 저장하지 않은 변경이 있는데 창을 닫거나 다른 템플릿으로 옮기려 하면 한 번 묻는다.

### 2.2 템플릿 불러오기

현장 견적의 항목 탭 도구 줄에 **"템플릿 불러오기"** 버튼을 둔다. 현장 견적을 편집할 수 있을 때만 누를 수 있다.

1. **템플릿 고르기**: 목록에서 하나를 고른다. 고르면 그 템플릿의 내용을 읽는다.
2. **공사 고르기**: 템플릿 안에 있는 카테고리 목록과 공간 목록을 체크박스로 보여 준다. 처음에는 모두 켜져 있다.
   - 칸마다 항목 수를 함께 보여 준다(예: 타일 12, 욕실 18).
   - 카테고리가 빈 줄은 "(카테고리 없음)", 공간이 빈 줄은 "(공간 없음)" 칸으로 따로 고른다.
   - 줄은 그 줄의 카테고리 칸과 공간 칸이 **둘 다** 켜져 있을 때만 들어온다.
   - 카테고리 목록·공간 목록마다 "모두 켜기 / 모두 끄기"가 있다.
3. **미리보기**: 체크할 때마다 불러올 항목 수, 최신 단가 기준 고객 합계, 템플릿 단가와 달라진 항목 수,
   DB에서 못 찾은 항목 수를 바로 다시 보여 준다. 미리보기는 지금 화면에 있는 자재 DB로 계산한다.
4. **불러오기**: 불러올 항목이 0개면 버튼이 눌리지 않는다. 누르면
   1. 자재 DB가 최신인지 확인한다(3.3). 확인에 실패하면 불러오기를 멈추고 다시 시도하라고 알린다.
      예전 단가로 몰래 불러오지 않는다.
   2. 최신 자재 DB로 단가를 다시 계산한다(4장). 미리보기와 숫자가 달라질 수 있고, 결과 안내에 최종 숫자가 나온다.
   3. 견적에 줄이 없으면 바로 넣는다. 있으면 "기존 항목 지우고 바꾸기 / 뒤에 덧붙이기 / 취소"를 묻는다.
      바꾸기는 저장하기 전까지는 기존 견적 화면의 저장 안 함 상태와 같아서, 저장하지 않고 나가면 되돌릴 수 있다.
5. **결과 안내**: 넣은 항목 수, 단가가 바뀐 항목(품명, 템플릿 단가 → 새 단가), DB에서 못 찾은 항목(품명) 목록을
   보여 준다. 넣은 뒤에는 평소처럼 고치고 저장한다. 템플릿 불러오기 자체는 현장 견적을 저장하지 않는다.

## 3. 저장

### 3.1 템플릿 저장소

Firestore 새 컬렉션 `estimateTemplates`. 문서 하나가 템플릿 하나다. 최근 기능(현장 기록·할 일)처럼
**Firestore에만** 저장하고, 서버의 서비스 계정으로만 읽고 쓴다. 예전 Sanity 저장 방식은 지원하지 않는다.
Firestore ERP가 꺼진 환경에서는 템플릿 버튼이 "템플릿은 Firestore에서만 쓸 수 있어요"라고 안내한다.

문서 필드:

| 필드 | 내용 |
|---|---|
| `name` | 템플릿 이름. 앞뒤 공백 제거, 1~60자, 다른 템플릿과 겹치지 않음(공백·대소문자 무시) |
| `linesJson` | 견적 줄 배열(JSON 문자열). 현장 견적의 `linesJson`과 같은 모양 |
| `lineCount` | 줄 수 (목록 표시용) |
| `customerTotal` | 템플릿 단가 기준 고객 합계 (목록 표시용) |
| `createdAt`, `updatedAt` | ISO 시각 |
| `createdBy`, `updatedBy` | 직원 이름 |

- 목록은 `name, lineCount, customerTotal, updatedAt, updatedBy`만 읽는다(필드 마스크). 템플릿 내용(`linesJson`)은
  작업 화면을 열거나 불러오기에서 고를 때 그 하나만 읽는다.
- 줄은 2,000줄까지 저장한다. 넘으면 저장 전에 "템플릿을 나눠 주세요"라고 알린다. 한 줄은 약 0.3~0.4KB라서
  2,000줄은 약 0.8MB로 Firestore 문서 한도(1MB) 안이다.
- **동시 수정 보호**: 템플릿을 읽을 때 Firestore `updateTime`을 함께 받아 두고, 저장할 때 그 `updateTime`이
  그대로일 때만 쓴다(PR #19의 견적 저장 보호와 같은 방식). 새로 만들 때는 `exists: false`로 쓴다. 충돌이면 409로
  알리고, 화면은 "다른 곳에서 먼저 고쳤어요"와 함께 **상대 내용 다시 불러오기 / 내 작업을 다른 이름으로 저장**을
  고르게 한다. 삭제된 템플릿을 저장하려 하면 "삭제된 템플릿이에요"라고 알리고 목록을 새로 고친다.
- **권한**: `estimates` 권한이 있는 직원만 목록·내용 읽기, 만들기, 고치기, 지우기를 할 수 있다.

### 3.2 견적 줄이 DB 항목을 기억하기

`EstimateLine`에 선택 필드 `materialId?: string`을 더한다. 자재 DB에서 줄을 채우는 곳(`materialToLine`)에서
그 DB 항목의 `_id`를 넣는다. 템플릿 작업 화면과 현장 견적 모두 같다.

- 이미 저장된 현장 견적은 바꾸지 않는다. 앞으로 DB에서 고르는 줄부터 기억한다.
- 줄의 품명·규격 등을 손으로 고쳐도 `materialId`는 그대로 둔다(단가를 따라갈 DB 항목은 그대로이므로).
  DB에서 다른 항목을 다시 고르면 새 항목의 id로 바뀐다.
- 직원 앱 견적 보기(`app/lib/mobile-estimate.ts`)는 보낼 필드만 골라 복사하므로 `materialId`는 휴대폰으로 가지 않는다.
  이를 테스트로 확인한다.

### 3.3 자재 DB가 최신인지 확인하기

자재 DB는 문서가 자재마다 하나라서 전체를 읽으면 자재 개수만큼 읽기가 든다. 그래서 불러오기 때마다 전체를 읽지 않는다.

1. 서버의 자재 DB 버전(`estimateMaterialMeta`의 `version`, 자재 저장·삭제·엑셀 올리기 때마다 갱신됨)만 읽는다.
   새 GET `part=materialsMeta`가 이 문서 하나만 읽어 돌려준다(읽기 1번).
2. 화면에 있는 자재 DB의 버전과 같으면 그대로 쓴다.
3. 다르면 지금 견적 화면이 하는 것과 같이 `part=materials`로 전체를 새로 읽고, 화면과 브라우저 저장 자재 DB도
   새것으로 바꾼다.

## 4. 최신 단가 찾기

불러오는 줄마다 아래 순서로 DB 항목을 찾는다.

1. `materialId`가 있고 그 id의 DB 항목이 있으면 그 항목.
2. 없으면, 줄의 품명·규격·단위가 모두 같은(앞뒤 공백 무시) DB 항목이 **정확히 하나**일 때 그 항목.
   공통 항목 줄(`commonName: true`)은 품명을 바꿔 쓰므로 이 순서를 쓰지 않는다.
3. 둘 다 아니면 찾지 못한 줄이다.

찾은 줄: 고객 단가와 실행 단가를 DB 단가로, 규격·단위를 DB 값으로 바꾸고 `materialId`를 그 항목으로 맞춘다.
품명은 공통 항목이면 템플릿 품명을 그대로, 아니면 DB 품명으로 둔다. 공간·카테고리·공정·수량·비고는 템플릿 그대로다.
템플릿의 고객 단가 또는 실행 단가가 DB 단가와 다르면 "단가가 바뀐 항목"으로 센다.

찾지 못한 줄: 템플릿에 적힌 값 그대로 들어오고 "DB에서 못 찾음"으로 센다.

모든 불러온 줄은 새 줄 id를 받는다. 같은 템플릿을 두 번 불러오거나 덧붙여도 줄 id가 겹치지 않는다.

## 5. 오류 처리

| 상황 | 동작 |
|---|---|
| 자재 DB 버전 확인·새로 읽기 실패 | 불러오기를 멈추고 다시 시도 안내 |
| 템플릿 저장 충돌 | 409, 상대 내용 다시 불러오기 / 다른 이름으로 저장 중 선택 |
| 템플릿 저장 실패 | 작업 창을 닫지 않고 입력 내용 유지 |
| 삭제된 템플릿 열기·저장·불러오기 | "삭제된 템플릿이에요" 안내 후 목록 새로 고침 |
| 이름이 비었거나 겹침, 60자 초과 | 저장 전에 안내 (서버도 같은 규칙으로 막음) |
| 2,000줄 초과 | 저장 전에 안내 (서버도 막음) |
| 로그인 만료·권한 없음 | 견적 화면과 같은 안내 |
| 불러올 항목 0개 | 불러오기 버튼 비활성 |

## 6. 코드 구성

- `app/lib/estimate-templates.ts` (새, 화면·서버 없는 순수 로직): 템플릿 줄 정리, 카테고리·공간 선택 목록과 개수,
  선택으로 거르기, 최신 단가 찾기와 결과 요약, 새 줄 id 붙이기, 이름·크기 검사. 테스트가 직접 가져온다.
- `app/api/manager/_estimate-templates.ts` (새): Firestore `estimateTemplates` 목록·하나 읽기(+`updateTime`)·
  조건부 저장·삭제.
- `app/api/manager/estimate/route.ts`: GET `part=templates`, `part=template&id=`, `part=materialsMeta`;
  POST `saveTemplate`, `deleteTemplate`. 모두 `estimates` 권한.
- `app/manager-weve-7519/estimate/template-manager.tsx` (새): 템플릿 관리 창과 작업 화면.
- `app/manager-weve-7519/estimate/template-load-dialog.tsx` (새): 불러오기 창(고르기·미리보기·결과 안내).
- `app/manager-weve-7519/estimate/page.tsx`: `EstimateLine.materialId`, `materialToLine`, 두 버튼, 불러온 줄을
  견적에 넣기, 자재 DB 최신 확인. 자재 고르기 창은 새 파일들이 쓸 수 있게 넘겨준다.
- `docs/WEVE_WORKING_RULES.md`: 템플릿 규칙 한 절.

## 7. 테스트

자동 테스트(`tests/estimate-templates.test.mjs`, `npm test`):

- 선택 목록: 카테고리·공간별 개수, 빈 칸은 "(카테고리 없음)"·"(공간 없음)".
- 거르기: 카테고리·공간을 둘 다 켠 줄만 남는다. 예: 타일 켜고 욕실 끄면 거실·주방 타일만 남는다.
- 단가 찾기: `materialId` 일치, 품명·규격·단위 하나 일치, 같은 줄이 여럿이면 못 찾음, 삭제된 자재, 공통 항목은 품명
  유지·이름 일치 안 씀, 바뀐 항목·못 찾은 항목 개수.
