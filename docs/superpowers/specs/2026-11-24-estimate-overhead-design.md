# 견적 공과잡비(3%)와 DB 카테고리 단추

작성일: 2026-11-24 · 상태: 검토 대기 · 크기: 작은 변경(짧은 설계)

## 왜
고객 견적에 공과잡비(공사비의 3%)를 넣어 서류에 한 줄로 보여 주려고 한다(대표님 요청). DB 패널의 카테고리 단추가 10개까지만 보여 나머지 카테고리를 단추로 고를 수 없다.

## 정한 것 (대표님 답변)
- 공과잡비는 고객 견적 금액에 **더하고**, 서류에 한 줄로 보여 준다.
- 방식 A: 견적 표의 품목이 아니라 **따로 계산하는 줄**. 견적 버전마다 비율을 저장한다.
- 기본 3%. 이미 저장된 견적은 0%(지금 금액 그대로), 새로 만드는 견적부터 3%.

## 설계
- **데이터:** 견적 버전에 `overheadRate`(%, 0-20, 소수 첫째 자리까지)를 저장한다. 저장된 값이 없는 예전 견적은 0으로 읽는다.
  - 빈 새 버전은 3이다. 다른 버전을 복사해 만든 새 버전은 원래 버전의 비율을 그대로 쓴다(고객에게 드린 금액 흐름이 바뀌지 않게).
- **계산 (화면과 서버 같은 규칙, 순수 함수 + 테스트):**
  - 공사비 = 품목 금액 합계(지금의 견적 합계)
  - 공과잡비 = 공사비 × 비율, 원 단위 반올림
  - **견적 금액(customerEstimateTotal) = 공사비 + 공과잡비**
  - 서버가 저장하는 견적 금액도 같은 값이라, 매출 관리·대시보드·현장 화면의 견적 금액에 자동으로 들어간다.
  - 예상·실제 마진은 이 견적 금액으로 계산한다. 공과잡비는 원가가 없어 그만큼 마진이 늘어난다. 실행 원가는 그대로다.
- **화면:** 견적서 화면의 금액 요약 옆에 '공과잡비 [3]% · 금액' 입력을 둔다. 0%로 두면 서류에서 그 줄이 빠진다.
- **서류(가로 서류 미리보기·인쇄·여러 서류 출력):**
  - 갑지: 공사 목록 아래 '공과잡비 (3%)' 줄, 그 아래 합계(= 견적 금액)
  - 세부내역서: 마지막 쪽 총합계 바로 위에 '공과잡비 (3%)' 줄. 쪽 나누기 높이 계산에도 포함한다.
  - 표지: 견적금액(한글 금액 포함)이 공과잡비를 포함한 금액이 된다.
  - 견적서 화면 오른쪽 세부내역서 미리보기에도 합계 위에 같은 줄을 보여 준다(템플릿 화면에는 없음).
- **휴대폰 앱 견적 보기:** 합계 위에 공과잡비 줄을 보여 주고, 합계에 더한다.
- **DB 카테고리 단추:** 견적서 DB 패널의 빠른 단추를 10개 제한 없이 모든 카테고리로 보여 준다(넘치면 다음 줄).

## 하지 않는 것
- 기업이윤·안전관리비 같은 다른 항목, 공과잡비를 공사마다 나눠 넣기, 템플릿에 비율 저장.
- 쓰이지 않는 옛 서류 부품(EstimateDocumentPreview, BatchEstimatePage, PrintPreview)은 손대지 않는다.
