# 매니저 사용 설명서 PDF: 통합 매니저와 견적 작업

작성일: 2026-10-23 · 상태: 검토 대기

## 1. 목적과 범위

매니저 화면에는 기능과 버튼이 많아서 처음 온 직원이 혼자 익히기 어렵다. 화면 캡처와 짧은 설명으로 된 PDF 사용
설명서 두 권을 만들고, 매니저 안에서 버튼 하나로 내려받게 한다.

- 통합 매니저 설명서: `/manager-weve-7519`의 모든 탭
- 견적 작업 설명서: `/manager-weve-7519/estimate`의 모든 탭

성공 기준:

- 두 설명서가 PDF로 있고, 각 화면의 버튼으로 내려받을 수 있다.
- 목차의 각 줄을 누르면 PDF 안의 그 쪽으로 이동한다.
- 자세한 설명이 필요한 곳에는 본문에 [부록 A-n] 표시가 있고, 누르면 부록의 그 쪽으로 이동한다. 부록 쪽에는 본문으로
  돌아가는 링크가 있다.
- 캡처에는 실제 고객 정보가 하나도 없다(가짜 데이터만).
- 화면이 바뀌면 명령 하나로 캡처와 PDF를 다시 만든다.

### 결정 사항 (대표님 답변, 2026-10-23)

| 질문 | 결정 |
|---|---|
| 포함 범위 | 모든 탭. 통합 매니저 12개 탭(홈페이지 하위 탭 포함)과 견적 페이지 7개 탭. 계정 권한·휴지통은 '관리자 전용' 표시 |
| PDF 만드는 때 | 미리 만들어 사이트와 함께 올린다(누를 때마다 만들지 않음) |
| 캡처 갱신 | 저장소에 '다시 만들기' 도구를 둔다. 설명 문구는 설명서마다 파일 하나에 모은다 |
| 내려받을 수 있는 사람 | 로그인한 직원만. 서버가 로그인을 확인한 뒤에 파일을 준다. 견적 설명서는 견적 권한이 있어야 한다 |
| 쪽 모양 | 예시 화면대로: A4 세로, 한 쪽에 화면 하나, 화면 위 빨간 번호와 아래 번호 설명이 짝 |
| 버튼 위치 | 통합 매니저는 머리글 로그아웃 앞, 견적 페이지는 제목 옆 |

### 하지 않는 것

직원 휴대폰 앱(`/m`) 설명서, 버튼을 누를 때마다 PDF 만들기, 권한에 따라 설명서 내용을 다르게 만들기, 영어 설명서,
설명서 안의 동영상.

## 2. 화면

### 2.1 다운로드 버튼

- 통합 매니저: 머리글 오른쪽, 로그아웃 바로 앞에 `사용 설명서`(책 아이콘) 버튼. 로그인 후에만 보인다(머리글 자체가
  로그인 후에만 보인다).
- 견적 작업 페이지: 머리글 왼쪽 제목(`현장별 견적 작업`) 옆에 같은 버튼. 저장 버튼과 떨어뜨려 잘못 누르지 않게 한다.
- 누르면 `/api/manager/manual?book=office|estimate`를 로그인 토큰과 함께 불러 받은 파일을 바로 내려받는다. 받는 동안
  버튼은 '받는 중…'으로 바뀌고 다시 누를 수 없다.
- 실패하면 그 페이지의 기존 오류 문구 자리에 알린다. 401이면 "로그인이 끝났습니다. 다시 로그인해 주세요.", 403이면
  "이 설명서를 받을 권한이 없습니다.", 그 밖에는 "설명서를 내려받지 못했습니다. 잠시 후 다시 시도해 주세요."
- 내려받는 파일 이름: `WEVE 통합 매니저 사용 설명서.pdf`, `WEVE 견적 작업 사용 설명서.pdf`

### 2.2 PDF 쪽 구성

A4 세로. 순서는 표지 → 목차 → 본문 → 부록이다.

- 표지: WEVE DESIGN, 설명서 이름, 'YYYY년 M월 화면 기준'(만든 날짜로 자동). 통합 매니저 설명서 표지에는 견적 작업
  페이지는 견적 설명서를 따로 받으라는 안내가 있다.
- 목차: 장(1. 시작하기 …)과 절(1-1 …), 부록(A-1 …)을 쪽 번호와 함께 싣는다. 줄 전체가 링크다.
- 본문 한 쪽: 위쪽 머리줄(장 이름 · 절 이름), 절 제목, 화면 캡처 하나, 번호 설명 목록, 필요하면 '💡' 도움말 한 줄,
  아래쪽 가운데 쪽 번호. 캡처 위 빨간 동그라미 번호(필요하면 빨간 테두리 상자)와 설명 번호가 짝이다. 설명 끝의
  [부록 A-n]은 그 부록 쪽으로 가는 링크다.
- 부록 한 쪽: '부록 A-n' 머리, 제목, 글과 표, 맨 아래 '← n-n 절 이름으로 돌아가기' 링크(처음 그 부록을 가리킨 절).
- 관리자만 쓰는 화면의 절 제목 옆에는 '관리자 전용' 표시를 붙인다.
- 한 쪽에 다 들어가지 않는 내용은 쪽을 나눈다(같은 절의 다음 쪽). 내용이 쪽을 넘치면 도구가 멈춘다(4.4).

## 3. 설명서 목차

### 3.1 통합 매니저

1. 시작하기: 로그인, 화면 구성(왼쪽 메뉴·머리글·세부 메뉴), 사용 설명서 받기
2. 업무 현황: 대시보드 보는 법, 현장별 바로 보기, 일일 보고서와 고객 진행 현황 올리기 [부록]
3. 고객·현장: 상담 요청(상세·완료 처리), 고객 관리, 현장 관리(고객 진행 현황 링크 [부록], 할 일·현장 기록), 매출 관리
4. 견적 관리: 견적 작업 탭과 견적 페이지 여는 법(자세한 것은 견적 설명서)
5. 자재·협력업체: 재고 관리, 협력업체
6. 홈페이지·채널: 홈페이지(기본 정보, 첫 화면, 섹션 문구, 연락처, 팝업, 프로젝트, 상담 설문), 외부 채널
7. 계정 권한(관리자 전용): 계정 만들기와 권한, 알림 받을 휴대폰, 휴대폰 로그인 기기
8. 휴지통(관리자 전용)

부록: A-1 메뉴별 권한 표, A-2 고객 진행 현황 링크가 만들어지고 닫히는 규칙, A-3 일일 보고서를 고객에게 올릴 때
(고객에게 보이는 것과 안 보이는 것), A-4 휴지통과 완전 삭제, A-5 새 상담이 들어오면(알림톡·이메일·휴대폰 알림, 카카오
상담 동기화)

### 3.2 견적 작업

1. 시작하기: 견적 페이지 여는 법, 화면 구성(현장 선택·저장·저장 안 된 변경), 견적 버전 [부록]
2. 견적서: 공사별 표, 줄 추가와 줄 메뉴, 도구 메뉴, 자재 DB에서 고르기, 공통 항목 한번에 추가, 템플릿 불러오기 [부록],
   이 견적을 템플릿으로 저장, 템플릿 관리
3. 실행 내역서
4. 자재 / 견적 단가
5. 공정 일정: 공정 달력, 바 우클릭 메뉴, 일정 상세, 휴일, 달력 출력 [부록]
6. 발주서
7. 추가 사항
8. 서류 출력: 견적 표지, 견적 갑지, 세부내역서, 추가 사항, 여러 서류 출력

부록: B-1 견적 버전(초안·수정안·최종안·변경견적), B-2 템플릿을 불러올 때 단가가 정해지는 규칙, B-3 평형 수량 조정 계산,
B-4 달력 출력(월별·공사 시작부터)

절과 부록은 만들면서 화면을 보고 늘거나 줄 수 있다. 정해진 것은 모든 탭을 담는다는 것과 부록 항목의 주제다.

## 4. 다시 만들기 도구

### 4.1 쓰는 법

```
npm run manuals
```

- `http://localhost:3000`에 개발 서버가 떠 있으면 그것을 쓰고, 없으면 도구가 `next dev`를 3000번으로 띄웠다가 끝나면
  끈다. `--base <주소>`로 다른 주소를 쓸 수 있다.
- 크롬은 `CHROME_PATH`, 없으면 Windows·macOS·Linux의 보통 설치 위치에서 Chrome, 그다음 Edge를 찾는다. 추가로 설치할
  npm 패키지는 없다(Node 24의 기본 WebSocket으로 크롬 개발자 도구 프로토콜(CDP)을 직접 쓴다).
- 결과: `manuals/office.pdf`, `manuals/estimate.pdf`. 둘 다 저장소에 커밋한다. `public/` 밖이라 주소로 바로 열 수 없다.
- `--only office|estimate`로 하나만 만들 수 있다.

### 4.2 파일

| 파일 | 하는 일 |
|---|---|
| `scripts/manuals/build-manuals.mjs` | 진입점. 서버·크롬 준비, 설명서별 캡처 → HTML → PDF → 확인 |
| `scripts/manuals/cdp.mjs` | 작은 CDP 클라이언트: 크롬 띄우기, 명령 보내기, 기다리기, 캡처, PDF 인쇄 |
| `scripts/manuals/mock-data.mjs` | 가짜 데이터와, 페이지에 끼워 넣는 로그인·`fetch` 가짜 응답 스크립트 |
| `scripts/manuals/office-manual.mjs` | 통합 매니저 설명서 내용: 장·절, 캡처 순서, 번호 위치, 설명, 부록 |
| `scripts/manuals/estimate-manual.mjs` | 견적 작업 설명서 내용 |
| `scripts/manuals/layout.mjs` | 내용 → 인쇄용 HTML(표지·목차·본문·부록, 쪽 번호) |
| `scripts/manuals/pdf-links.mjs` | PDF의 쪽·링크·목적지를 읽는 작은 해석기(도구의 확인과 테스트가 함께 쓴다) |
| `manuals/office.pdf`, `manuals/estimate.pdf` | 결과물 |

### 4.3 캡처

- 가짜 로그인과 가짜 데이터: 도구가 페이지가 열리기 전에(CDP `Page.addScriptToEvaluateOnNewDocument`) 스크립트를
  끼워 넣는다. 이 스크립트는 탭 세션(`weve-manager-session-v2`)에 가짜 총괄 관리자 세션을 넣고, `window.fetch`를 감싸
  `/api/manager/*`와 `/api/integrations/*`에는 가짜 응답을, 나머지는 원래대로 보낸다. 가짜 응답 스크립트는 앱 코드에
  들어가지 않고 도구만 쓴다. 데모 페이지를 만들지 않는다.
- 가짜 데이터는 누가 봐도 지어낸 것으로 만든다: 이름 홍길동·김예시·이샘플 같은 이름, 전화 `010-0000-xxxx`, 주소 '가나시
  다라동'. 실제 고객·현장·업체 이름을 쓰지 않는다.
- 가짜 응답에 없는 API를 페이지가 부르면 빈 응답을 주고, 도구가 끝날 때 그 목록을 보여 준다.
- 창 크기 1440×900. 각 캡처는 내용 파일의 순서대로 움직인다: 메뉴 글자를 눌러 탭 열기, 버튼 누르기, 우클릭, 스크롤,
  잠깐 기다리기. 캡처는 화면 전체 또는 지정한 부분만.
- 번호 붙이기: 내용 파일은 번호마다 대상을 화면 글자(예: `'현장 저장'`) 또는 CSS 선택자로 적는다. 도구가 그 요소를 찾아
  위치를 재고, 페이지 위에 빨간 동그라미 번호(와 원하면 테두리 상자)를 그린 다음 캡처한다. 그래서 버튼이 옮겨져도 번호가
  따라간다. 대상을 못 찾거나 여러 개라 어느 것인지 모르면 도구가 그 절 이름과 함께 멈춘다.
- 개발 서버의 Next.js 표시(왼쪽 아래 'N' 단추)와 '로그인 상태를 복원했습니다.' 같은 상태 문구는 캡처 전에 감춘다.
- 캡처는 JPEG로 저장한다. PDF가 4MB를 넘으면 품질을 낮추지 말고 도구가 멈춘다. 그때는 캡처를 부분으로 자르거나 품질
  설정을 고친다.

### 4.4 PDF와 확인

- 인쇄용 HTML은 쪽마다 A4 크기(210×297mm) 상자 하나다. 크롬 `Page.printToPDF`로 PDF를 만든다(머리글·바닥글 없음,
  배경 인쇄). 같은 문서 안 링크(`href="#..."`)는 PDF 안 이동 링크가 된다(시험으로 확인함).
- 인쇄 전에 확인: 어느 쪽 상자도 내용이 넘치지 않는다(넘치면 그 쪽 이름과 함께 멈춘다).
- 인쇄 후 확인(`pdf-links.mjs`):
  - PDF 쪽 수 = 만든 쪽 상자 수
  - 모든 링크는 PDF 안 목적지로 가고(바깥 주소 링크 없음), 그 목적지는 그 절·부록이 실제로 있는 쪽이다
  - 목차의 모든 절·부록이 링크로 있다. 본문의 모든 [부록] 표시가 있는 부록을 가리킨다. 모든 부록에 돌아가기 링크가 있다
  - 파일 크기 4,000,000바이트 이하
- 하나라도 틀리면 PDF를 쓰지 않고 멈춘다(예전 PDF가 남는다).

## 5. 서버: `GET /api/manager/manual`

- `book` 값: `office` 또는 `estimate`. 그 밖은 400 "알 수 없는 설명서입니다."
- 권한: `requireManager`. `office`는 로그인만(규칙 없음), `estimate`는 `anyOf: ['estimates']`. 설명서와 권한, 파일
  이름의 표는 `app/lib/manager-manuals.ts`에 두고 라우트와 화면이 같이 쓴다.
- 파일은 `manuals/<book>.pdf`를 읽어 보낸다. Vercel 배포에 파일이 들어가도록 `next.config.ts`에
  `outputFileTracingIncludes: { '/api/manager/manual': ['./manuals/*.pdf'] }`를 둔다. 파일이 없으면 404 "설명서 파일이
  없습니다. 관리자에게 문의해 주세요."
- 응답 머리: `Content-Type: application/pdf`, `Content-Disposition: attachment; filename="weve-<book>-manual.pdf";
  filename*=UTF-8''<한글 파일 이름>`, `Cache-Control: private, no-store`.
- 크기: Vercel 함수는 응답 본문이 4.5MB를 넘으면 보내지 못하므로 PDF를 4MB 이하로 지킨다(4.4).

## 6. 테스트

`npm test`(node:test)에 `tests/manager-manuals.test.mjs`를 더한다.

- 라우트: 토큰 없음 401, 알 수 없는 `book` 400, 견적 권한 없는 직원의 `estimate` 403, 권한 없는 직원도 `office`는 200,
  관리자는 둘 다 200. 200이면 PDF 바이트(`%PDF-`로 시작)와 위 응답 머리.
- 저장된 두 PDF: 4MB 이하, 쪽 수 2 이상, 모든 링크가 PDF 안의 있는 쪽으로 간다, 바깥 주소 링크 없음.
- `manager-manuals.ts`의 표: 두 설명서의 권한 규칙과 파일 이름.
- `next.config.ts`의 파일 포함 설정이 `manuals/*.pdf`를 담는다.

그 밖에 `npx tsc --noEmit -p .`, `npm run build`, 그리고 가짜 데이터 화면에서 두 버튼을 직접 눌러 내려받기와
PDF 링크 이동을 확인한다.

쓴다, PDF는 4MB 이하, 로그인한 직원만(견적 설명서는 견적 권한) 받는다, 화면을 크게 바꾸면 설명서도 다시 만든다.
